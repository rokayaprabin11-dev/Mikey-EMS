# Data model

The PostgreSQL schema, implemented in `packages/db/prisma/schema.prisma`. Change this file in the same commit as any schema change.

Conventions:

- Table names `snake_case` plural; Prisma models `PascalCase` singular with `@@map`.
- Primary keys: `id` UUID generated by PostgreSQL (`gen_random_uuid()`), except counters and settings.
- Every table has `created_at timestamptz default now()` and `created_by` (user id, nullable for `system`). `created_by` is a plain id without a foreign key. Where a table names who created a row and when (`taken_by`, `entered_by`, `requested_by`/`requested_at`, `voided_by`/`voided_at`, `closed_by`/`closed_at`, `corrected_by`/`corrected_at`, `printed_by`/`printed_at`, `allowed_by`/`allowed_at`, `audit_logs.user_id`/`at`), those columns take the place of `created_by`/`created_at`, and the named user columns are foreign keys.
- Money columns end in `_paisa` and are `bigint`. Business dates end in `_date` and are `date` (AD). Moments end in `_at` and are `timestamptz`. Times of day are `HH:MM` text (Kathmandu wall clock).
- `computer` columns hold 1 or 2.
- **Financial tables have no `updated_at` and no delete path.** Database triggers reject `UPDATE`, `DELETE` and `TRUNCATE` on `payments`, `payment_allocations`, `receipts`, `receipt_prints`, `original_print_allowances`, `voids`, `incomes`, `expenses`, `transfers`, `account_entries`, `day_closes`, `day_close_prints` and `audit_logs`. Editable tables have `updated_at` and an integer `version` for optimistic locking.
- The status of a payment, income or expense is worked out, never stored: **voided** if a row in `voids` points at it, **void requested** if a `pending` row in `void_requests` points at it, otherwise **posted**.
- A row that points at exactly one of several tables has one nullable foreign key per table and a `CHECK` that exactly one is set.
- Every foreign key is `ON DELETE RESTRICT`.
- `CHECK` constraints and the triggers are written by hand in the migration SQL, because Prisma cannot express them. Partial unique indexes use Prisma's `partialIndexes` preview feature.
- Soft status instead of delete for people: `status` = `active` | `inactive`.
- Tables marked *(later)* are not in the Accountant build; they arrive with the screens that use them.

Wrong passwords are counted from `audit_logs` (ARCHITECTURE.md, Sessions and auth). Sign-in bookkeeping does not change `version` |

| `classes` | name (`Play Group`…`Class 10`, unique), sort_order | |
| `sections` | class_id, name (`A`), sort_order | Unique (class_id, name) |

## Payments and receipts

| Table | Key columns | Notes |
| --- | --- | --- |
| `payments` | student_id, idempotency_key (unique), paid_date, method, reference?, amount_paisa, account_id, taken_by, computer | No status column (see conventions). A cash payment has no reference; every other method has one (`CHECK`). Unique (id, amount_paisa), so a receipt's amount can be tied to its payment |
| `payment_allocations` | payment_id, fee_due_id?, fine_id?, amount_paisa | Exactly one of fee_due_id / fine_id. A due or fine appears once per payment |
| `receipts` | payment_id (unique), receipt_no (unique, `2083/84-001285`), fiscal_year (`2083/84`), seq, amount_paisa, dues_before_paisa, discount_paisa, balance_after_paisa, snapshot (jsonb) | Unique (fiscal_year, seq). `receipt_no` = fiscal_year + `-` + seq padded to 6 digits (`CHECK`). `amount_paisa` is always the payment's amount (foreign key on (payment_id, amount_paisa)). `dues_before_paisa` is the student's whole outstanding (dues and fines, less discounts already on them) just before the payment; `discount_paisa` is the discounts on the dues this receipt pays, for information; `balance_after_paisa` = dues before − amount. All three ≥ 0 (`CHECK`). `snapshot` is everything printed on the receipt (`receiptSnapshotSchema` in packages/shared); receipt PDFs and the API's receipt come only from it (DOMAIN_RULES.md §5) |
| `receipt_counters` | fiscal_year (PK), last_seq | Locked `FOR UPDATE` when issuing |
| `receipt_prints` | receipt_id, print_no, computer, printed_by, printed_at, allowance_id? (unique) | Unique (receipt_id, print_no). Print 1 is the original; a print with an `allowance_id` is the one more original that allowance permitted; every other print is a copy, marked "Copy of original, print #N". The print count is the number of rows |
| `original_print_allowances` | receipt_id, reason, allowed_by, allowed_at | The Super Admin's permission for one more original after a failed print. Reason never blank (`CHECK`). Used up by the print that points at it. Insert only |
| `void_requests` | payment_id? / income_id? / expense_id?, reason_code (`wrong_student`, `wrong_amount`, `wrong_method`, `other`), details, status (`pending`, `approved`, `declined`), requested_by, requested_at, decided_by?, decided_at?, decision_note?, direct | Exactly one target. At most one pending request per record (partial unique indexes). `details` is never empty. `direct` marks a void the Super Admin made in one step; a direct request is approved and was decided by the person who made it (check) |
| `voids` | payment_id? / income_id? / expense_id? (each unique), reason_code, note?, void_request_id? (unique), voided_by, voided_at | Exactly one target; one void per record |
